02 / Setup

Up and running in four steps.

No scripts, no containers, no config files to hand-edit. Download two things, wire them up, and you have a fully private local AI stack.

1

Download LM Studio

Get the macOS app from lmstudio.ai. Open it, go to the Developer tab, and click Start Server. The OpenAI-compatible API comes up at localhost:1234 automatically.

SettingValue
API basehttp://localhost:1234/v1
API keyDeveloper → API Keys → generate one, save to .secrets
2

Download models

In LM Studio → Discover, search for each model and click Download. Start with the primary; add others as needed.

google/gemma-4-e4b9.02 GBPrimary — daily chat & coding (GGUF Q8_0, multimodal)

3

Wire up your tools

Point each tool at http://localhost:1234/v1. All three use the same OpenAI-compatible endpoint.

To switch between LM Studio and Ollama at any time:

Enjoy

Open your editor, run pi or opencode in the terminal, or press ⌘L in VS Code. Everything runs locally — no API costs, no data leaving your Mac.

03 / Models

⚠️ With 24 GB unified memory, ~14–16 GB is available for models after macOS overhead. Swap models as needed — unloading takes a second.

07 / Open WebUI

Beyond basic chat.

Open WebUI has powerful features built in. All settings live in Admin Panel — click your avatar → Admin Panel → Settings.

✓ Pipelines container is running at localhost:9099 — started automatically by ai-stack-start.

1 · RAG / Knowledge Base

Upload documents — PDFs, Word files, receipts, Swift docs — and let the model answer questions from them using semantic search. Far more accurate than keyword matching.

1

Set the embedding model

Admin Panel → Settings → Documents. Set Embedding Model to text-embedding-nomic-embed-text-v1.5 (served by LM Studio). Save.

2

Create a Knowledge collection

Workspace → Knowledge → New Knowledge. Give it a name, then upload PDFs, Word files, or any documents you want to query.

3

Use in chat

Click + in a new chat → select your Knowledge collection. Or use 📎 to attach a single file directly. Ask questions about the content — the model retrieves relevant passages and cites them.

💡 Best local model for RAG: granite-3.3-8b-instruct for multilingual 128K-context document Q&A. Use phi-4-reasoning when the task is mostly reasoning rather than retrieval.

2 · Memory

Open WebUI remembers facts across conversations — your name, that you do iOS dev, your current projects — building a personal context that persists between sessions.

1

Enable Memory

Admin Panel → Settings → Personalization. Toggle Memory on. Save.

2

Seed your memory (optional)

Profile → Memory. Add facts manually: "I'm an iOS developer using Swift 6 and TCA" or "I work on local AI infrastructure on Apple Silicon".

3

Let it build automatically

During conversations the model extracts and saves relevant facts. Review and edit any time in Profile → Memory.

3 · Code Execution (Artifacts)

Models can write Python or JavaScript and run it inline, showing output. Ideal for data processing, quick calculations, or verifying code snippets.

1

Enable Code Interpreter

Admin Panel → Settings → Interface. Toggle Code Interpreter (or "Artifacts") on. Save.

2

Ask the model to run code

Ask naturally: "Plot this dataset as a bar chart" or "Write and run a Python script to parse this CSV". A Run button appears — tap to execute and see output inline.

⚠️ Code runs inside the Open WebUI Podman container — sandboxed and safe.

09 / Agents

Automation & agents.

Three patterns for putting a local model to work unattended, in increasing order of risk. An agent that can run shell commands is not a better cron job — pick by what the task actually needs.

PatternToolWhat it doesRisk
Workflow automationn8n + local endpointYou define the logic; the model is one node. Versionable, debuggable. Digests, monitoring, scheduled reports.Low
Messaging agentOpenClawTelegram/WhatsApp/Discord. Heartbeat daemon every 30 min. Reads files, manages calendars — and executes commands on the host.High
Desktop automationHermes AgentPlaywright browser control, cron, dashboard. Needs 64K context minimum from the endpoint.High
⚠️ Hermes remote access is a known open issue (NousResearch/hermes-agent#84865). hermes serve shows a login page but disables the web UI — you need hermes dashboard. OAuth registration on a VPN host fails with redirect_uri_mismatch, and the MagicDNS workaround is undocumented.
💡 NemoClaw was evaluated and does not fit. NVIDIA’s sandboxed OpenClaw variant is attractive — the agent reaches neither host filesystem nor host network — but it requires Docker, and this stack is container-free by design. Its primary target is DGX Spark or a 24 GB+ NVIDIA GPU on Ubuntu; the Apple Silicon host-to-sandbox inference bridge is incomplete.

Reaching them remotely

SSH and Screen Sharing toggles live in System Settings on the Mac mini — the machine being connected to. Clients need nothing beyond the tailnet.

SurfaceHowOpen ports
Tailscale Serve — any web dashboardtailscale serve --bg 3000 — automatic HTTPS via MagicDNS, stable hostnameNone
Messaging — Telegram, DiscordAgent long-polls outward. Works from anywhere, no tailnet needed on the clientNone
OpenAI-compatible APIhttp://<tailscale-ip>:1234/v1 from any chat clientLAN only
SSH — shell access to the miniOn the mini: enable Remote Login in Sharing settings. From a client: ssh simone@<mini>.tailXXXX.ts.netTailnet only
Screen Sharing — remote desktopOn the mini: Sharing settings → Screen Sharing (plain VNC). From a client: any VNC app, or Screens on iOS/iPadOS, to <mini>.tailXXXX.ts.net:5900Tailnet only
⚠️ Skip Remote Management (Apple Remote Desktop — fleet/MDM tooling). It shares port 5900 with Screen Sharing and takes over when enabled. One mini, one admin: Screen Sharing alone is correct here.
⚠️ FileVault can lock the mini out on reboot. It needs its password at the pre-boot decryption screen — before Tailscale, SSH, or Screen Sharing have even started. A power flicker or update then leaves it unreachable until someone is physically at the keyboard. Disable FileVault for a headless box, or confirm macOS Tahoe 26.5+'s remote unlock actually works over Tailscale before trusting it. Also enable automatic login (Users & Groups) — the same lockout risk exists one layer up at the user login screen.
⚠️ Never use tailscale funnel for any of these — Funnel publishes to the public internet and defeats the whole design. The inference endpoint has no authentication of its own; the tailnet is the only thing protecting it.

Before enabling agent tooling

ConcernWhy it matters here
Prompt injectionThe dominant failure mode. Models don’t separate instructions from data — every web page, email and stranger’s message the agent reads is untrusted input that can issue commands.
Quantization is a security parameterAggressively quantized checkpoints raise injection risk. UD-IQ3_S is fine for chat, questionable for an agent with shell access — prefer UD-IQ4_XS and recheck the memory budget.
