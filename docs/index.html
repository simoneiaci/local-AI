02 / Setup

Up and running in four steps.

No scripts, no containers, no config files to hand-edit. Download two things, wire them up, and you have a fully private local AI stack.

1

Download LM Studio

Get the macOS app from lmstudio.ai. Open it, go to the Developer tab, and click Start Server. The OpenAI-compatible API comes up at localhost:1234 automatically.

SettingValue
API basehttp://localhost:1234/v1
API keyDeveloper → API Keys → generate one, save to .secrets
2

Download models

In LM Studio → Discover, search for each model and click Download. Start with the primary; add others as needed.

ModelSizeRole
google/gemma-4-e4b6.33 GBPrimary — daily chat & coding
mlx-community/gemma-4-26b-a4b-instruct-4bit~16 GBHeavy — load alone when quality matters
granite-3.3-8b-instruct4.94 GBTool-calling & multilingual RAG
phi-4-reasoning11.12 GBReasoning & math — load alone
smollm2-1.7b-instruct1.82 GBTab autocomplete in VS Code
text-embedding-nomic-embed-text-v1.584 MBEmbeddings for RAG
⚠️ Only one large model at a time. Load gemma-4-26b or phi-4-reasoning alone — eject the primary first.
3

Wire up your tools

Point each tool at http://localhost:1234/v1. All three use the same OpenAI-compatible endpoint.

ToolConfig locationModel to set
Pi~/.pi/agent/settings.json → provider lmstudiogoogle/gemma-4-e4b
Continue.dev~/.continue/config.json → provider lmstudiogoogle/gemma-4-e4b · autocomplete: smollm2-1.7b-instruct
OpenCode~/.config/opencode/opencode.json → provider lmstudiogoogle/gemma-4-e4b

To switch between LM Studio and Ollama at any time:

ai-use-mlx     # LM Studio :1234 (default)
ai-use-ollama  # Ollama :11434
4

Enjoy

Open your editor, run pi or opencode in the terminal, or press ⌘L in VS Code. Everything runs locally — no API costs, no data leaving your Mac.

✓ Stack is ready. Primary model loaded at localhost:1234 — all tools are pointing at it.
03 / Models

Right model for every task.

Models run locally through LM Studio by default, with Ollama available as an alternate runtime. Only one large model fits in RAM at a time — smollm2-1.7b-instruct and text-embedding-nomic-embed-text-v1.5 stay loaded alongside any other.

⚠️ With 24 GB unified memory, ~14–16 GB is available for models after macOS overhead. Swap models as needed — unloading takes a second.
memory budget · 24 GB unified RAM
💡 For granite-3.3-8b-instruct in LM Studio, set the model's default Context Length to 32K in My Models → gear icon. Use 64K only for long-document sessions; avoid 128K as the everyday default on this 24 GB laptop.

Control API

The dashboard proxies start/stop buttons to the host control server on port 9091. Requests without CONTROL_TOKEN are rejected:

POST http://localhost:9091/control
Authorization: Bearer <CONTROL_TOKEN>

{"action": "ollama_stop"}     # or: ollama_start
{"action": "lmstudio_stop"}   # or: lmstudio_start
{"action": "webui_stop"}      # or: webui_start
{"action": "pipelines_stop"}  # or: pipelines_start
{"action": "podman_stop"}     # or: podman_start

Useful Commands

podman logs local-ai-dashboard      # container logs

06 / Web Search

Live internet access, fully local.

Give your local models live internet access. Search results are fetched and summarised privately, right inside Open WebUI — nothing leaves your Mac.

✓ Web search is active. Engine: SearXNG — self-hosted on port 8080, zero external requests, unlimited searches.

How It Works

Open WebUI has built-in web search. When enabled, a 🌐 button appears in every chat. Toggle it before sending a message — the model searches the web, reads the top results, and cites its sources, all without leaving your Mac.

Using Search in Open WebUI

1

Open a chat

Go to localhost:3000 and open any conversation.

2

Enable web search

Click the 🌐 icon in the message bar before sending your prompt.

3

Ask your question

The model searches SearXNG, reads the top results, and cites sources inline. All traffic stays on your Mac.

07 / Open WebUI

Beyond basic chat.

Open WebUI has powerful features built in. All settings live in Admin Panel — click your avatar → Admin Panel → Settings.

✓ Pipelines container is running at localhost:9099 — started automatically by ai-stack-start.

1 · RAG / Knowledge Base

Upload documents — PDFs, Word files, receipts, Swift docs — and let the model answer questions from them using semantic search. Far more accurate than keyword matching.

1

Set the embedding model

Admin Panel → Settings → Documents. Set Embedding Model to text-embedding-nomic-embed-text-v1.5 (served by LM Studio). Save.

2

Create a Knowledge collection

Workspace → Knowledge → New Knowledge. Give it a name, then upload PDFs, Word files, or any documents you want to query.

3

Use in chat

Click + in a new chat → select your Knowledge collection. Or use 📎 to attach a single file directly. Ask questions about the content — the model retrieves relevant passages and cites them.

💡 Best local model for RAG: granite-3.3-8b-instruct for multilingual 128K-context document Q&A. Use phi-4-reasoning when the task is mostly reasoning rather than retrieval.

2 · Memory

Open WebUI remembers facts across conversations — your name, that you do iOS dev, your current projects — building a personal context that persists between sessions.

1

Enable Memory

Admin Panel → Settings → Personalization. Toggle Memory on. Save.

2

Seed your memory (optional)

Profile → Memory. Add facts manually: "I'm an iOS developer using Swift 6 and TCA" or "I work on local AI infrastructure on Apple Silicon".

3

Let it build automatically

During conversations the model extracts and saves relevant facts. Review and edit any time in Profile → Memory.

3 · Code Execution (Artifacts)

Models can write Python or JavaScript and run it inline, showing output. Ideal for data processing, quick calculations, or verifying code snippets.

1

Enable Code Interpreter

Admin Panel → Settings → Interface. Toggle Code Interpreter (or "Artifacts") on. Save.

2

Ask the model to run code

Ask naturally: "Plot this dataset as a bar chart" or "Write and run a Python script to parse this CSV". A Run button appears — tap to execute and see output inline.

⚠️ Code runs inside the Open WebUI Podman container — sandboxed and safe.

4 · Pipelines

Custom Python middleware that intercepts every message. Use it to auto-translate Italian documents, post-process model output, add rate limiting, or inject context automatically.

1

Verify the Pipelines container

podman ps | grep pipelines
# Should show open-webui-pipelines on port 9099
2

Connection settings

Admin Panel → Settings → Connections → OpenAI API → add:

FieldValue
URLhttp://host.containers.internal:9099
API Key0p3n-w3bu!

Click Verify — green checkmark confirms it's connected.

3

Install a pipeline

Admin Panel → Pipelines → Install from GitHub URL or upload a .py file. Browse examples at github.com/open-webui/pipelines.

5 · Image Input (Vision)

Use a vision-capable model and attach an image in Open WebUI. google/gemma-4-e4b supports image input. Useful for reading receipts, Xcode error screenshots, diagrams, or scanned documents.

Use casePrompt example
Xcode errorAttach screenshot → "What's wrong and how do I fix this?"
Receipt scanAttach photo → "List all items and amounts."
UI sketchAttach wireframe → "Write SwiftUI code for this layout"
Bank statementAttach PDF screenshot → "Summarise all transactions above €500"

6 · Custom Modelfiles (Personas)

Custom models pre-loaded with expert system prompts. Create them in Open WebUI's Workspace → Models.

1

Create a persona in Open WebUI

Workspace → Models → Create Model. Choose google/gemma-4-e4b as base, write a System Prompt, save. Appears immediately in the chat selector.

2

Create a new persona

Workspace → Models → Create Model. Choose a base model, write a System Prompt, save. Appears immediately in the chat selector.

3

Or via Ollama CLI

cat > ~/my-assistant.modelfile <<'EOF'
# Personal-only; no corporate/work data
FROM phi-4-reasoning
SYSTEM """You are a helpful assistant..."""
EOF
ollama create my-assistant -f ~/my-assistant.modelfile
